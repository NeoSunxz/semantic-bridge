# Semantic Bridge v1 — Implementation plan

Status: confirmed by the owner · 2026-11-04. Scope and behaviour: [design spec](../specs/2026-11-03-semantic-bridge-design.md).

## Layout

One executable hosts both the CLI and `sbridge mcp`.

```
semantic-bridge.sln
src/SemanticBridge.Core/                 classlib, net10.0
src/SemanticBridge/                      exe, AssemblyName=sbridge, PackAsTool, ToolCommandName=sbridge
tests/SemanticBridge.Tests/              unit tests, no network
tests/SemanticBridge.IntegrationTests/   skipped unless SBRIDGE_IT_* env vars are set
Directory.Build.props, Directory.Packages.props (central versions), global.json (SDK 10.0)
```

Core areas: `Config` (loader, profiles, cloud presets, secret resolution), `Auth` (`ITokenProvider`, one client-secret implementation — the seam for later interactive auth), `Rest` (Power BI REST client), `Xmla` (ADOMD queries/metadata, TOM description writes), `Results` (`QueryResult`, `RowCap` — every row-collecting path goes through it), `Safety` (`SecretScrubber`, `WriteGate`, `DaxGuard`). CLI and MCP both call one Core service facade so their semantics stay identical.

## Decisions

- XMLA auth: MSAL token via `AdomdConnection.AccessToken` preferred (no secret in any connection string); fall back to `User ID=app:{clientId}@{tenantId}` only if the Phase 0 spike shows the token path fails.
- China authority default `https://login.partner.microsoftonline.cn`; China XMLA host is verified by the owner's production, not by Microsoft docs.
- REST `executeQueries` does not support INFO functions: Pro (REST-only) workspaces get query only; `schema --via rest` fails with a clear message. Documented.
- REST truncation can arrive as HTTP 200 with an error object and partial data; it must set `truncated: true`.
- XMLA workspace names must be URI-encoded; duplicate names need the `Name - <guid>` form.
- Defaults: `max_rows` 1000, configurable ceiling up to 100000; `query_timeout_seconds` 120, clamped 1..600.
- Release all six RIDs; only linux-x64 is live-verified, the rest are labelled "XMLA unverified".
- No RLS/roles in v1.
- ADOMD/TOM ship under a Microsoft EULA: read the redistribution terms before any release; stop and ask the owner if unclear.

## Phases

| 5 | README, config template, `THIRD-PARTY-NOTICES.md` | No |

Each phase is one implementer task; acceptance is `dotnet build`, `dotnet test`, `dotnet format --verify-no-changes` plus the phase's own checks.
